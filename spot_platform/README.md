# 电力现货市场出清仿真平台（日前市场 · 96 时段 · 双侧分段申报）

依据《开发要求》实现的课程设计平台：日前市场 24 小时 = **96 个 15 分钟时段**，
发电侧与用户侧均以 **N≤10 段阶梯报价**申报，交易中心统一出清、公布电价并结算收支。
纯 C++17 标准库，g++ 或 Makefile 编译，无需 CMake。

## 功能与《开发要求》对照

| 要求 | 实现 |
|------|------|
| 发电侧 (1) 提交申报表单 | 内置示例数据，或 `--gen-bids 文件.csv` 导入 |
| 发电侧 (2)(3) 查看出清结果/电价/收入 | `--role gen` |
| 用户侧 (4) 提交申报表单 | `--con-bids 文件.csv` 导入 |
| 用户侧 (5)(6) 查看出清结果/电价/账单 | `--role con` |
| 交易中心 (7) 查看所有主体申报表单 | `--role center` 打印全部申报表单 |
| 交易中心 (8) 出清并公布电价 | 96 时段逐时出清并打印/导出 |
| 交易中心 (9) 计算收支 | 统一边际价结算，自动收支平衡校验 |
| (10) 二次曲线进阶 | `--module quadratic`（边际成本定价 + 二分反函数校验） |
| (11) 其他功能 | CSV 导入/导出、申报自检（`--selftest`）、供不应求触顶处理 |

**申报规则校验**（不合规拒绝并说明原因）：段数 N≤10；数量 > 0；报价 ≥ 0；
发电侧报价单调非递减 C1≤…≤CN；用户侧单调非递增 CN≤…≤C1。

**出清算法**：每个 15 分钟时段独立出清——发电段按报价升序构成供给阶梯 S(p)，
用户段按报价降序构成需求阶梯 D(p)，扫描首个 S(p\*) ≥ D(p\*) 的报价为出清价
P\*，出清量 Q\* = min(S(P\*), D(P\*))；优于边际价的段全中标、边际价段部分中标；
供需报价不交叉则该时段不出清，供给总量不足则价格触顶 1500 元/MWh。

**结算**：发电收入 = 用户账单 = P\* × 中标量 × 0.25h，全天收支差额自动校验为 0。

## 编译

```bash
# 方法一：g++ 直接编译
g++ -std=c++17 -O2 -Wall -Wextra -o spot_platform main.cpp market.cpp

# 方法二：Makefile
make          # 编译
make run      # 编译并运行全部模式
make test     # 运行自检
```

> Windows 中文控制台：cmd/PowerShell 先 `chcp 65001`（Git Bash 用 `chcp.com 65001`）。

## 运行

```bash
./spot_platform                            # 全部模式 + 全部角色视角
./spot_platform --module spot --role center   # 仅交易中心视角
./spot_platform --role gen                 # 发电侧：出清结果/电价/收入
./spot_platform --role con                 # 用户侧：出清结果/电价/账单
./spot_platform --module quadratic --load 900   # 二次曲线进阶
./spot_platform --selftest                 # 校验自检（12 个用例）
./spot_platform --gen-bids gen.csv --con-bids con.csv   # 自定义申报
./spot_platform --web-io in.tsv out.json   # 网页后端模式：TSV 申报 → JSON 结果
```

### 网页后端模式（--web-io）

供可视化网页的后端调用：从 TSV 文件读取申报，出清后把**全部结果写成 JSON**
（96 时段出清/边际机组、各主体结算、峰平谷账单、KPI、二次曲线三档结果），
网页前端只负责渲染、不做任何运算。

输入 TSV（Tab 分隔，UTF-8），每行一个报价段：

```
G<TAB>电厂名称<TAB>数量MW<TAB>报价
C<TAB>分型<TAB>用户名称<TAB>数量MW<TAB>报价     # 分型：0=低谷 1=平段 2=高峰
```

校验失败等错误会输出 `{"error":"说明"}` 并以非零码退出。
配套的网页见 `../spot_platform_web/`（`npm run dev` 启动后打开页面即可）。

## 申报表单 CSV 格式

首行表头自动跳过；每行一个报价段，同一主体多行即多段：

```csv
电厂名称,机组编号,时段,出力MW,报价
XX电厂,#1机组,-1,150,200        # 时段=-1：适用于全部 96 时段
XX电厂,#1机组,-1,100,260
XX电厂,#2机组,36,120,400        # 时段 0~95：逐时段申报（未报的时段=不申报）
```

用户侧同理：`用户名称,用户编号,时段,负荷MW,报价`。

## 内置示例数据

- **发电侧**：清流电厂 #1 水电（150@200 / 100@260 / 50@330）、望江电厂 #2 火电
  （120@400 / 100@480 / 80@560）、云峰电厂 #3 燃气（60@620 / 40@700），全时段通用申报。
- **用户侧**：临江钢铁 U1、星洲商业 U2 按 低谷(00–07,23–24)/平段/高峰(18–22)
  三档逐时段申报，高峰用电量最大。
- **出清结果**：低谷 330 元、平段 480 元、高峰 620 元，峰谷价差 290 元/MWh；
  高峰时段 #3 燃气为边际机组（60 MW 中部分中标 50 MW）。
- **二次曲线示例**：C(Q)=0.0005Q²+0.2Q+200，容量 1000 MW；负荷与阶梯出清一致，
  分低谷 280 / 平段 470 / 高峰 650 MW 三档，出清价 P\*=C(Qd) 分别为
  295.20 / 404.45 / 541.25 元/MWh，峰谷价差 246.05 元/MWh；
  `--load <MW>` 可改为自定义单档负荷。

## 输出文件

| 文件 | 内容 |
|------|------|
| `bids_gen.csv` / `bids_con.csv` | 全部主体申报表单（交易中心视角） |
| `clearing_96.csv` | 96 时段出清价/出清量/各主体中标量明细 |
| `settlement.csv` | 各主体电量与收支 + 收支平衡校验 |
| `quadratic.csv` | 二次曲线出清参数与结果 |

CSV 均带 UTF-8 BOM 并按 RFC 4180 转义，可直接用 Excel 打开。

## 教学简化说明

- 96 个时段**独立出清**，不考虑爬坡、启停成本、网损与辅助服务；
- 出清价取阶梯交叉点处卖方段报价（统一边际价），未采用报价对半等其它定价规则；
- 供不应求时价格直接触顶 1500 元/MWh。
